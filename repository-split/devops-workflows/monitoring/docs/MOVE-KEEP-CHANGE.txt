RELEASE ORDER: TWO REAL CENTRAL COMMIT IDS ARE REQUIRED
Placeholders are deliberate and MUST be replaced before using the callers.
GitHub does not substitute a variable inside a reusable-workflow uses reference.

1. Keep all four CICD_MONITOR automation/publish flags false in doc_extraction.
2. In devops-workflows, first commit/merge actions/nwb-cicd-monitoring and monitoring/.
   Do not install the two reusable YAML files with unresolved action references.
   Record the full 40-character commit SHA after merge. Call this ACTION_SHA.
3. In BOTH reusable YAML files replace REPLACE_WITH_ACTION_COMMIT_SHA with ACTION_SHA.
   Example shape (use a real SHA, not this text):
   uses: northwest/devops-workflows/actions/nwb-cicd-monitoring@<ACTION_SHA>
4. Commit/merge those finalized reusable workflows into devops-workflows.
   Record that full merged commit SHA. Call this WORKFLOW_SHA.
5. In BOTH caller YAML files replace REPLACE_WITH_WORKFLOW_COMMIT_SHA with WORKFLOW_SHA.
   The same WORKFLOW_SHA contains both reusable workflow files.
6. In a doc_extraction PR, replace the two existing monitoring YAML files using
   those finalized callers. Keep the existing configuration and scripts for now.
7. Merge the reviewed caller PR into doc_extraction's default branch.

ACTION_SHA and WORKFLOW_SHA usually differ. The first identifies scripts and the
composite action; the second identifies workflows that call that exact action.
This avoids a self-referencing commit ID and makes upgrades explicit. Future
releases follow the same action -> workflow -> caller sequence.

ADMIN CONFIGURATION
In devops-workflows: Settings > Actions > General > Access. Allow use by approved
repositories in the northwest organization, according to the bank's policy.
In each caller: allow the central reusable workflows and composite action plus
the approved checkout and Azure Login actions. Runner access must allow the CALLER.
No personal access token or secrets: inherit is added. GitHub supplies the source
repo token and downloads the allowed shared action. The action's scripts are read
from github.action_path, so no cross-repository git checkout credential is needed.

The caller retains contents:read, actions:read, deployments:read (collector), and
id-token:write. id-token:write enables requesting an OIDC token; Azure DCR access
still requires federation and Monitoring Metrics Publisher. The reusable workflow
cannot elevate the token permissions provided by the caller.

Azure federation must trust the CALLER's identity/environment. For the pilot, check
the existing federation with show_identity=true and publish=false. If trust also
restricts job_workflow_ref, update it to the reviewed reusable workflow reference.
For each new repo, confirm its own federation and identity permissions with admin.
Do not assume the doc_extraction federation automatically trusts another repo.

3. Confirm the run calls the reusable workflow and loads the pinned central action.
4. Confirm preview records say Repository=northwest/doc_extraction and preserve
